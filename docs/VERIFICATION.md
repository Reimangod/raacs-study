# Automated verification

Here, **continuous integration** means the GitHub Actions software checks.
**Configuration interaction (CI)** is the classical electronic-structure
calculation. They are different uses of the same abbreviation.

## Checks and their scope

| Check | What runs | What it establishes | What it does not establish |
|---|---|---|---|
| Core tests | Python 3.11, 3.12, and 3.13 on Ubuntu | Portable saved-data behavior, accounting distinctions, archive path handling, and included evidence hashes | Fresh molecular construction or scientific superiority |
| Saved-result parity | Rebuild all 42 portable output files | Byte-identical summary, reproduction metadata, and 40 SVG plots | Completeness of an unrecorded experiment or independent source trials |
| Saved-basis CI | Two existing LiH bases, at most 16 determinants | Energy/residual parity within the stated tolerance and explicit spin/phase convention | Validation of every molecular CI root or FCI reference |
| Documentation | Local links/anchors, English prose, and safe documentation SVGs | Navigable first-party documentation and no active/external SVG content | Availability of every external website |
| Installed wheel | Build and install the package into a fresh environment | The packaged CLI can import, display help, and verify the included repository | Automatic redistribution of multi-GiB raw data inside the wheel |

The [workflow](../.github/workflows/test.yml) runs on pushes, pull requests, and
manual dispatch. Jobs use read-only repository permissions, pinned action
commits, a fixed uv version, and explicit Python versions. Redundant runs on the
same branch are cancelled. No job launches an acquisition, contacts a QPU, needs
an A100, downloads the raw archives, or changes a release.

Small JSON/JUnit reports and the built package are retained as workflow
artifacts for seven days. Reports belong to the tested commit/run; they do not
overwrite the historical records in `verification/`. Failed checks remain failed
even when diagnostic artifacts are uploaded.

## Run the same checks locally

```sh
uv sync --locked --extra test
uv run --no-sync pytest -q --junitxml=.ci-reports/pytest.xml
uv run --no-sync python scripts/check_docs.py --repo . --output .ci-reports/docs.json
uv run --no-sync python scripts/check_reproduction.py --repo . --output .ci-reports/reproduction.json
```

For the bounded numerical check:

```sh
uv sync --locked --extra science
uv run --no-sync raacs-study ci-check --repo . --output .ci-reports/saved-ci.json
```

`check_reproduction.py` writes to a temporary directory and compares every
portable product with `results/`; it never refreshes the committed results or
their evidence manifest. `results/README.md` and the separately created
`figure-sources.csv` provenance index are not generated by this command and
are covered by the included-file hash check instead.

## English documentation without rewriting evidence

Current guides, comments in maintained tools, and new explanatory diagrams use
English. Legacy documentation paths redirect to English guides. Original
historical code, identifiers, raw tables, source inventories, and fixed-release
assets retain their captured bytes and original language. Translating them
would invalidate the scientific provenance.

The documentation checker validates local links without network access. This
keeps an external service outage from being mistaken for a software or science
regression. External references still require human review when their scientific
content is used.

## Separate, expensive verification

Full archive downloads, original-byte reconciliation, rights review, and full
fresh molecular regeneration are separate tasks. Their existing verification
records are preserved; routine Actions success does not silently re-certify
those layers. See [reproduction](REPRODUCTION.md), [limitations](LIMITATIONS.md),
and [the fixed-release status](STATUS.md).

and [workflow syntax and permissions](https://docs.github.com/en/actions/reference/workflows-and-actions/workflow-syntax).
