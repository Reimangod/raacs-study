# Rights and publication status

Initial delivery is a **private** GitHub repository and private release assets.
No unrelated repository visibility is changed. No Zenodo deposit is fabricated.

The owner approved MIT for newly written packaging tools and CC BY 4.0 for
independently owned data on 2026-10-31. Those grants are now recorded in LICENSE
and LICENSE-DATA.md. The historical third-party distribution review is separate.

Before public release:

1. Apply the approved scope of the packaging-code and data licenses. Do not
   apply them to third-party code by implication.
2. Check historical code ownership, retain upstream license/notice files and
   record upstream commits and modifications. Unknown lineage stays unknown.
3. Review selected files for credentials, private correspondence and redistribution
   restrictions. Automated pattern scans are not a guarantee of secret absence.
4. Fix a release tag, code commit and data checksums, then archive those exact
   materials in Zenodo. Cite the **specific-version DOI** in the paper.
5. Download deposited files and verify hashes and completeness. GitHub release
   attachments/LFS payload must not be assumed automatically archived by another
   service. Assign separate code/data records if useful, with reciprocal links.

Zenodo access is not configured by this package. A private GitHub release is a
working delivery, not a public long-term repository or DOI-backed publication.

The broad private history includes one publisher supplementary PDF whose public
redistribution permission was not established here, and legacy native binaries.
These are identified in verification/rights-review.json. Do not switch this
entire private backup public or feed it wholesale to Zenodo without addressing
those items. They are not a blocker to saved-data use by the owner privately.
