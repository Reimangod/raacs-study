# RAACS research archive: execution instructions

Read README.md and docs/SCOPE.md before changes. Shell commands use `rtk`.

- This repository packages existing research. It does not authorize new molecular
  sampling, source optimization, Slurm jobs, or changes to historical evidence.
- Source workspace files are read-only. Copy original bytes and record SHA-256;
  make corrected/portable products as explicitly labelled derivatives.
- B4 is a historical method ID. RAACS is its current display name only for the
  registered B4 implementation. ACTIVE and other exploratory policies are not B4.
- Keep cohorts, readout spin rules, finite model shots, actual CI dimensions,
  resource conventions and missingness distinct. Never manufacture unknown values.
- Original endpoint rows, independent source constructions, CI roots and shots
  are different units. Do not sum endpoint rows as independent experiments.
- Do not overwrite archives or paper tags. A corrected release is a new version.
- Upload only explicitly enumerated files. Exclude environments, secrets, private
  correspondence and unrelated CEO compression/NN studies.
- Default remote visibility is private. DOI publication and public visibility
  require completed rights review and explicit recorded release scope.
- Never run archived scripts indiscriminately: some submit jobs or write to old
  absolute paths. Use the documented safe reproduction entrypoints.
- Core tests must be CPU-only and small. Full archive verification is separate.
- Keep maintained documentation and new diagrams in English. Original-language
  historical evidence is exempt and must retain its exact captured bytes.
- For documentation/CI edits, run the tests plus scripts/check_docs.py and
  scripts/check_reproduction.py. Write transient reports under .ci-reports/;
  never replace the original verification records or reseal changed evidence.
- Run tests, source-preservation checks and a fresh-clone reproduction before
  claiming a release is verified. Record unverified layers honestly.
